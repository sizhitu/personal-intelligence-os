# Web workbench\n\nA responsive, local-first static prototype. No build step, API key, or backend is required.\n\n## Live preview\n\nhttps://sizhitu.github.io/personal-intelligence-os/\n\n## Features\n- Register decisions with goals, domains, hard constraints, alternatives, success hypotheses, metrics, exposure limits, stop/rollback rules, and review dates.\n- Capture the current decision factor weights and visualize their relative profile.\n- Pre-register experiments linked to decisions, including anticipated failure modes, exposure caps, stop conditions, and expected information value.\n- Review outcomes and classify informative, preventable, poorly designed, successful, or mixed results; record evidence tier and next action.\n- Persist records in the current browser using localStorage; export/import JSON backups.\n- Surface saved decision records in the history view.\n\n## Data and privacy\n\nRecords stay in the browser profile on the device where they were entered. They are not synchronized to a server, account, or other device. Clearing browser storage can erase them; export JSON backups regularly. This prototype has no authentication, encryption-at-rest layer, multi-user access control, or cloud backup. Do not enter highly sensitive personal, customer, health, financial-account, or third-party data.\n\n## Publish\n\nGitHub Actions deploys the `web/` directory to GitHub Pages on pushes to `main`. Workflow: `.github/workflows/pages.yml`.\n\n## Current limitation\n\nThe workbench captures structured records and guides review. An optional AI adapter can send explicitly approved context to an OpenAI-compatible endpoint and save the returned analysis to a decision record. It does not perform autonomous live web research, validate citations, calculate statistically calibrated recommendations, or sync to a private database.\n

## Decision engine v0.4
`engine.js` runs a transparent deterministic model router and decision comparison flow. It loads static case seeds from `data/`, proposes contextual factors and weights, lists non-compensatory hard gates, prompts whole-system checks, retrieves candidate cases, and lets the user rate options. The deterministic router itself is not an LLM or live search. The option score is only a weighted calculation of user-entered ratings. Read [ENGINE_ARCHITECTURE.md](../ENGINE_ARCHITECTURE.md) for scope and limitations.


## AI reasoning adapter v0.4
- Optional OpenAI-compatible Chat Completions adapter; deterministic local engine remains usable without a key.
- API key is held only in page memory, is never written to localStorage or exported JSON, and is cleared on page exit/field blur. The provider receives the current decision context only after explicit consent. Recent decision/review history is a separate opt-in and is off by default.
- HTTPS endpoints only. Browser CORS/provider compatibility may vary. Never paste secrets or sensitive third-party/customer/health data into the prompt.
- AI snapshots can be attached to an existing local decision record and included in a user-created JSON backup. An additional unchecked-by-default control optionally shares up to five prior decision and experiment-review summaries for continuity. Model library and public case seeds are sent as context; citations must be verified.
- The prompt enforces pre-registered, bounded, safe, ethical, informative failures as learning; it does not celebrate preventable harm, reckless failures, or breaches of guardrails.


## Local-first core and optional AI extension
The decision workspace, rule-based model routing, hard-gate checks, factor weighting, experiment registration, reviews, relationship overview, decision history, local persistence, import, and export work without any AI provider or network access. The AI adapter is isolated on its own `AI 扩展（可选）` view; it provides a second opinion only. If the adapter script, API key, network, or provider is unavailable, core workflows remain usable. The graph and history views are sibling views, not children of the decision workspace.
